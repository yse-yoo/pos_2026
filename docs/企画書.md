# SmartPOS 企画書

**作成日:** 2026-05-29  
**システム名:** SmartPOS

---

## 1. 開発背景

小規模な店舗（クレープ屋・カフェ・フードスタンドなど）では、レジ業務・商品管理・売上確認を一元化できる手頃なシステムが求められている。しかし既存の商用POSシステムは導入コストが高く、使いこなすまでの学習コストも大きい。また、スタッフ全員がスマートフォンに慣れている現在の環境でありながら、PC専用の旧来型UIに縛られているケースも多い。

こうした課題に対して、Web ブラウザだけで動作し・スマートフォンにも対応した・シンプルで使いやすい POS システムを自社開発する。

---

## 2. 目的

| 目的 | 詳細 |
|------|------|
| 会計業務の効率化 | 商品選択から会計完了まで1画面で完結させ、操作ステップを最小化する |
| 商品管理の自己完結 | 管理者が外部ツールに依存せず、画面上で商品の追加・変更・削除ができる |
| 売上の可視化 | 会計ごとの売上履歴を蓄積し、いつでも確認できる |
| マルチデバイス対応 | PC・タブレット・スマートフォンのどの端末でも主要操作が完了できる |

---

## 3. ターゲットユーザ

| ユーザ種別 | 想定シーン | 主な権限 |
|------------|------------|----------|
| レジ担当スタッフ | 店頭での会計業務 | レジ画面の操作（商品選択・会計） |
| 店舗管理者 | 商品マスタの更新、売上確認 | 商品管理・売上履歴の閲覧・設定変更 |

**共通前提:**
- IT リテラシーは一般的なスマートフォンユーザレベルを想定
- 専門的なシステム知識は不要な操作性を目指す

---

## 4. 課題と解決策

### 4.1 会計業務

| 課題 | 解決策 |
|------|--------|
| 商品点数が多く探しにくい | カテゴリタブで絞り込み表示 |
| 数量ミスの修正が煩雑 | カート内で `+/-` ボタンにより数量をその場で変更 |
| 支払方法の柔軟性が低い | 現金・カード・QR・電子決済など複数の支払方法に対応 |
| 消費税の計算ミス | 税込合計を自動計算・自動表示 |

### 4.2 商品管理

| 課題 | 解決策 |
|------|--------|
| メニュー変更のたびに外部ツールが必要 | ブラウザから登録・編集・削除が完結するCRUD画面を提供 |
| 非販売商品がレジに表示されてしまう | 商品ごとに表示状態（表示中 / 非表示）を切り替え可能にする |
| 表示順の整理が困難 | 並び順フィールドで表示順を自由に制御できる |

### 4.3 売上管理

| 課題 | 解決策 |
|------|--------|
| 会計結果が後から確認できない | 会計ごとに売上データをバックエンドへ保存し、一覧・詳細で確認可能にする |
| スタッフが勝手に売上データを変更できてしまう | 売上履歴は管理者ログイン後にのみ閲覧可能にする |

---

## 5. 提供機能（画面構成）

| 画面 | URL | 概要 |
|------|-----|------|
| レジ画面 | `/pos` | 商品選択・カート管理・会計処理を1画面で完結 |
| 売上履歴画面 | `/sales/history` | 過去の会計一覧と詳細を確認 |
| 商品管理画面 | `/products` | 商品の一覧・登録・編集・削除（CRUD） |
| 商品登録画面 | `/products/create` | 新規商品の登録フォーム |
| 商品編集画面 | `/products/:id/edit` | 既存商品の編集フォーム |
| 管理者ログイン | ―  | 商品管理・売上履歴へのアクセス認証 |

---

## 6. 技術方針

| 項目 | 内容 |
|------|------|
| フロントエンド | React + TypeScript + Vite（SPA） |
| バックエンド | REST API（`/api/products`, `/api/sales`, `/api/categories`） |
| 状態管理 | React hooks（useCart・useProductCatalog・useSalesHistory） |
| スタイリング | カスタム CSS（エコグリーン系カラー、大きめ文字で視認性重視） |
| レスポンシブ | PC：テーブル表示 / SP：カード表示に自動切替 |
| 認証 | 管理者ログイン（商品管理・売上履歴はログイン必須） |

---

## 7. スコープ外（現フェーズ）

以下は現フェーズでは対象外とし、将来の拡張候補として位置づける。

- 在庫管理・原価管理
- 軽減税率（8%）対応
- バーコードスキャナー連携
- レシート印刷
- 売上集計・日次レポート
- 画像アップロード
- スタッフ別売上管理

---

## 8. システムテスト観点（品質目標）

| 観点 | 目標 |
|------|------|
| 操作性 | 初めて触るスタッフが、案内なしで会計を完了できる |
| 正確性 | 合計金額・消費税・伝票番号が正しく算出される |
| 一貫性 | 商品管理の変更がレジ画面にリアルタイムに反映される |
| 堅牢性 | API取得失敗時はエラーを画面内に明示し、再試行できる |
| レスポンシブ | スマートフォン幅でも主要操作が完了できる |
